

# Claude Code Scout — weekrapport 25 april 2026

## Samenvatting

Een buitengewoon rijke week met drie dominante thema's. **Ten eerste**: Anthropic publiceerde een postmortem over drie bugs in de Claude Code-harness die wekenlang kwaliteitsproblemen veroorzaakten — niet in de modellen, maar in de infrastructuur eromheen. Dit onderstreept het belang van deterministische vangnetten via hooks. **Ten tweede**: een academisch paper (arXiv) ontleedde de volledige Claude Code-codebase en onthulde dat slechts 1,6% AI-besluitvormingslogica bevat — de rest is deterministische infrastructuur. Dit valideert een architectuurbenadering waarbij je 98% van je effort in de harness steekt. **Ten derde**: Agent Teams zijn gelanceerd als nieuwe coördinatielaag boven subagents, en context rot management wordt steeds beter gedocumenteerd met concrete drempelwaarden (300k–600k tokens).

Omdat je systeemontwerp en huidige setup nog niet zijn ingevuld, worden alle inzichten als potentieel nieuw behandeld. Vul je setup-bestanden aan om volgende week gerichtere filtering te krijgen.

## Nieuwe inzichten per categorie

### Hooks

**Voorstel:** Verschuif kritieke regels van CLAUDE.md naar deterministische hooks
**Bron:** Knightli, knightli.com — https://www.knightli.com/en/2026/04/23/claude-code-claude-md-rules-memory-hooks-guide/
**Type:** fundamenteel
**Toelichting:** Hooks zijn de enige laag in de Claude Code-omgeving die van probabilistisch naar deterministisch gedrag overgaat. Regels in CLAUDE.md worden "meestal" gevolgd; hooks worden *altijd* uitgevoerd. Dit artikel legt helder uit wanneer je een regel moet omzetten naar een hook: als het breken ervan onacceptabele gevolgen heeft (force push, destructieve operaties, ontbrekende tests).

```yaml
# Voorbeeld: git force-push preventie als PreToolUse hook
# In .claude/settings.json:
hooks:
  PreToolUse:
    - matcher: "Bash"
      command: |
        if echo "$CLAUDE_TOOL_INPUT" | grep -q 'git push.*--force'; then
          echo "BLOCK: git force-push is niet toegestaan"
          exit 1
        fi
```

**Voorstel:** Gebruik recursion guards en lifecycle-event categorisatie voor schaalbare hook-architectuur
**Bron:** Blake Crosley, blakecrosley.com — https://blakecrosley.com/blog/claude-code-hooks
**Type:** fundamenteel
**Toelichting:** Met 95 hooks over 26 lifecycle events demonstreert dit de meest uitgebreide publieke hook-configuratie. Belangrijkste les: zonder recursion guards kunnen hooks zichzelf triggeren in oneindige loops. Het artikel categoriseert hooks in veiligheid (blokkeren), kwaliteit (valideren) en automatisering (transformeren), wat een bruikbaar denkraam biedt voor het prioriteren van je eerste hooks.

### Contextmanagement

## Paradigma-check

### 1. "Het model is het product" → Nee, de harness is het product

Het arXiv-paper bevestigt wat de postmortem al suggereerde: de drie bugs die wekenlang kwaliteitsproblemen veroorzaakten zaten niet in het model maar in de infrastructuur eromheen (reasoning depth throttling, caching-bug, tekstlengtebeperking). Gecombineerd met het gegeven dat 98,4% van Claude Code deterministische code is, verschuift het paradigma: **je bouwt geen prompt-engineering pipeline, je bouwt een softwaresysteem waarin een model is ingebed.**

*Implicatie:* Behandel je Claude Code-configuratie als een engineering-project met versiebeheer, tests en CI/CD — niet als een verzameling tips en trucs.

### 2. "Meer context = beter resultaat" → Nee, context discipline is essentieel

Meerdere bronnen deze week (mejba.me, techtaek.com, Nuno Roberto op Medium) convergeren op hetzelfde inzicht: het 1M context window verleidt tot het overloaden van context, maar kwaliteit degradeert meetbaar vanaf 300k tokens. **De frustrerende sessies die gebruikers toeschrijven aan "Claude wordt slechter" zijn vaak het gevolg van context-vervuiling.**

*Implicatie:* De vuistregel "nieuwe taak = nieuwe sessie" is niet optioneel efficiëntie-advies maar een kerncondition voor betrouwbare output.

### 3. "Subagents zijn de oplossing voor parallellisatie" → Agent Teams veranderen het speelveld

De introductie van Agent Teams (direct messaging tussen agents, gedeelde takenlijsten) maakt het traditionele subagent-patroon (alles via de lead-agent) potentieel verouderd voor complexere workflows. Dit is nog vroeg, maar het is een fundamentele architectuurwijziging die de bottleneck van één coördinator verwijdert.

*Implicatie:* Evalueer of je huidige subagent-workflows baat hebben bij Agent Teams, vooral als je merkt dat de lead-agent een communicatie-bottleneck vormt.

### 4. Vendor lock-in risico wordt reëel

Het Claude Code Pro-plan incident (tijdelijke verwijdering en backlash-gedreven terugdraaiing) en de opkomst van lokale modellen als alternatief voor routinetaken signaleren een groeiend risico. Teams die hun volledige workflow op Claude Code bouwen zonder escape-hatch zijn kwetsbaar voor prijswijzigingen en beschikbaarheidsproblemen.

*Implicatie:* Houd je deterministische lagen (hooks, CLAUDE.md, CI/CD-integraties) zo platformonafhankelijk mogelijk. De harness-architectuur moet overdraagbaar zijn.
