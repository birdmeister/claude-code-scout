## Nieuwe inzichten per categorie

### Beveiliging

**Voorstel:** Audit je hooks-, MCP- en environment-configuratie op supply-chain risico's bij het clonen van onbekende repositories
**Bron:** Check Point Research — [Caught in the Hook: RCE and API Token Exfiltration Through Claude Code Project Files](https://research.checkpoint.com/2026/rce-and-api-token-exfiltration-through-claude-code-project-files-cve-2025-59536/)
**Type:** fundamenteel
**Toelichting:** Drie kritieke kwetsbaarheden (CVE-2025-59536 en CVE-2026-21852) tonen aan dat malicious `.claude/` configuratiebestanden in een repository willekeurige code kunnen uitvoeren en API-sleutels kunnen exfiltreren zodra je het project opent. Dit raakt hooks, MCP-servers en environment variables — precies de drie pijlers van elke Claude Code setup. Elke gebruiker die repositories van derden cloned is kwetsbaar.

```yaml
# Implementatie-instructie
# 1. Review .claude/ directories VOOR je een onbekende repo opent
# 2. Gebruik sandboxing (zie volgende voorstel)
# 3. Voeg toe aan CLAUDE.md:
security:
  - Nooit automatisch hooks uit onvertrouwde repos uitvoeren
  - Review alle .claude/settings.json en hooks bij clone
  - Gebruik git hook pre-checkout scripts om .claude/ dirs te flaggen
```

### Agents & multi-agent workflows

**Voorstel:** Implementeer Agent Teams voor parallelle werkstromen met directe inter-agent communicatie
**Bron:** claudefa.st — [Claude Code Agent Teams: The Complete Guide 2026](https://claudefa.st/blog/guide/agents/agent-teams)
**Type:** fundamenteel
**Toelichting:** Agent Teams laten meerdere Claude Code sessies gecoördineerd werken: één sessie als teamlead die werk toewijst, terwijl teamgenoten onafhankelijk werken én direct met elkaar communiceren. Dit verschilt fundamenteel van subagents (die alleen via de parent communiceren) en is de oplossing voor complexe taken die parallel moeten verlopen.

```yaml
# Implementatie-instructie
# Agent Teams configuratie voorbeeld:
# 1. Definieer team in .claude/agents/team.yaml
team:
  lead: architect
  members:
    - role: frontend
      scope: "src/components/**"
    - role: backend
      scope: "src/api/**"
    - role: tests
      scope: "tests/**"
  communication: direct  # agents praten met elkaar
# 2. Start met: claude team start --config .claude/agents/team.yaml
```

---

**Voorstel:** Gebruik het Skills → Subagents → Agent Teams escalatiemodel
**Bron:** Dean Blank, Level Up Coding — [A Mental Model for Claude Code: Skills, Subagents, and Plugins](https://levelup.gitconnected.com/a-mental-model-for-claude-code-skills-subagents-and-plugins-3dea9924bf05)
**Type:** fundamenteel
**Toelichting:** Dit artikel biedt het helderste mentale model tot nu toe: Skills zijn kennis (altijd beschikbaar of on-demand), Subagents zijn workers (voor taken die je context zouden overbelasten), Agent Teams zijn workers die met elkaar praten (voor complexe, parallelle projecten). Begin bij CLAUDE.md voor universele regels, verplaats naar Skills voor specifieke workflows, en escaleer naar Subagents/Teams wanneer de complexiteit dat vereist.

```yaml
# Escalatiemodel:
# Niveau 1: CLAUDE.md — regels die ELKE sessie actief zijn
# Niveau 2: Skills (.claude/skills/) — specifieke workflows, on-demand
# Niveau 3: Subagents — wanneer een taak je context overbelast
# Niveau 4: Agent Teams — wanneer meerdere agents moeten coördineren
```

**Voorstel:** Laat agents volledige workflows autonoom afmaken — onderbreek niet mid-workflow

De aanbeveling: laat agents een complete feature bouwen tot aan een pull request, en review pas dan. Dit vereist vertrouwen in je guardrails (tests, linting, sandboxing) maar levert exponentieel meer productiviteit op.

### Skills & kennispakketten

**Voorstel:** Verplaats repetitieve prompt-patronen naar skill.md-bestanden in `.claude/skills/`
**Bron:** Towards Data Science — [Claude Skills and Subagents: Escaping the Prompt Engineering Hamster Wheel](https://towardsdatascience.com/claude-skills-and-subagents-escaping-the-prompt-engineering-hamster-wheel/)
**Type:** fundamenteel
**Toelichting:** Skills zijn herbruikbare instructiesets die Claude automatisch activeert wanneer relevant. In plaats van dezelfde prompts steeds te herhalen, codeer je ze als skill-bestanden. Dit elimineert de "prompt engineering hamster wheel" en standaardiseert kwaliteit.

```yaml
# Voorbeeld skill-bestand: .claude/skills/code-review/SKILL.md
# ---
# name: code-review
# description: Gestructureerde code review volgens teamstandaarden
# triggers:
#   - "review"
#   - "code review"
# ---
# ## Instructies
# 1. Controleer op security issues (SQL injection, XSS, etc.)
# 2. Verifieer error handling en edge cases
# 3. Check naamgeving en consistentie met bestaande codebase
# 4. Beoordeel testdekking
# 5. Geef feedback in format: [MUST FIX] / [SHOULD FIX] / [NICE TO HAVE]
```

### Geheugen & persistentie

**Voorstel:** Implementeer een persistent geheugen-systeem om contextverlies tussen sessies te voorkomen
**Bron:** Agent Native, Medium — [Persistent Memory for Claude Code: "Never Lose Context" Setup Guide](https://agentnativedev.medium.com/persistent-memory-for-claude-code-never-lose-context-setup-guide-2cb6c7f92c58)
**Type:** fundamenteel
**Toelichting:** Elke Claude Code sessie begint met een schone lei. Claude-Mem vangt automatisch tool-gebruiksobservaties, comprimeert ze in gestructureerde samenvattingen en slaat alles lokaal op in SQLite. Dit is het meest complete antwoord op het persistentieprobleem.

```yaml
# Implementatie-opties (kies één):

# Optie A: Claude-Mem (automatisch)
# git clone https://github.com/thedotmack/claude-mem
# Vangt automatisch observaties op en comprimeert naar SQLite

# Optie B: MCP Memory Server (enterprise-grade)
# Draai als systemd service met SSE-transport (niet stdio)
# Bron: crunchtools.com

# Optie C: TODO.md + CLAUDE.md (handmatig, lichtgewicht)
# TODO.md = live werkstatus (wat is gedaan, wat volgt)
# CLAUDE.md = handboek (regels, conventies)
# Memory = team wiki (besluiten, context)
```

### Hooks

**Voorstel:** Onderzoek HTTP hooks als alternatief voor lokale shell-scripts
**Bron:** claudefa.st — [Claude Code Hooks: Complete Guide to All 12 Lifecycle Events](https://claudefa.st/blog/tools/hooks/hooks-guide)
**Type:** klein
**Toelichting:** Claude Code ondersteunt nu vier typen hook handlers: command, HTTP, prompt en agent. HTTP hooks (sinds februari 2026) verzenden POST-requests naar endpoints in plaats van lokale shell-scripts uit te voeren. Dit opent mogelijkheden voor externe integraties (Slack notificaties, CI/CD triggers, logging services) zonder lokale scripts te onderhouden. Let wel op de beveiligingsimplicaties gezien de CVE's hierboven.

```yaml
# Voorbeeld HTTP hook configuratie:
# .claude/settings.json
hooks:
  PostToolUse:
    - type: http
      url: "https://je-webhook.example.com/claude-events"
      events: ["file_write", "bash_execute"]
      # WAARSCHUWING: Valideer altijd de bron bij onbekende repos
```

## Paradigma-check

### 1. "CLAUDE.md is altijd goed" → Niet per se

Het artikel van Codemanship stelt dat CLAUDE.md-bestanden kunnen lijden aan **aandachtsversplintering** (te veel regels → geen enkele regel heeft impact) en **context rot** (verouderde instructies = verkeerde kaart). De vraag is niet óf je CLAUDE.md moet hebben, maar of je kunt meten dat het werkt. **Aanbeveling:** Houd CLAUDE.md minimaal, verplaats specifieke workflows naar Skills, en review maandelijks.

### 2. "Prompt engineering is dé vaardigheid" → Skills maken het overbodig

Het Towards Data Science artikel stelt dat het steeds verfijnen van prompts een hamsterwiel is. De paradigmaverschuiving: codificeer je kennis als Skills en Subagents, zodat je niet elke sessie opnieuw dezelfde context moet opbouwen. **Dit verandert de kerncompetentie van "goed prompten" naar "goed systemen ontwerpen."**

### 3. "Menselijke tussenkomst verbetert AI-output" → Mid-workflow onderbreking vernietigt waarde

McKinsey's QuantumBlack toont aan dat de grootste productiviteitswinst komt van agents die volledige workflows autonoom afmaken. Menselijk ingrijpen halverwege reset de context en dwingt de agent tot heroriëntatie. **De implicatie:** investeer meer in guardrails vooraf (tests, sandboxing, linting) zodat je achteraf kunt reviewen in plaats van tussentijds bij te sturen.

### 4. "Eén Claude Code sessie per taak" → Parallellisatie is de primaire productiviteitsheboom

Zowel het Claude Code team (paddo.dev) als Anthropic zelf (C compiler blogpost) benadrukken dat 3-5 parallelle sessies in aparte worktrees de norm zou moeten zijn. Dit vereist een andere manier van denken over taakdecompositie en projectorganisatie.

### 5. "Beveiliging is een configuratiekeuze" → Het is een existentieel risico

De CVE-publicaties van deze week tonen aan dat de kracht van Claude Code (hooks, MCP, environment variables) tegelijk het grootste aanvalsoppervlak is. **Elke repository die je cloned kan willekeurige code uitvoeren.** Dit is geen randgeval maar een fundamenteel architectuurprobleem dat sandboxing en configuratie-audits verplicht maakt.
