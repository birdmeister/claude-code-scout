### Beveiliging

**Voorstel:** Audit je deny-regels — ze worden stilzwijgend genegeerd bij complexe commando's
**Bron:** adversa.ai — [Critical Claude Code vulnerability: Deny rules silently bypassed](https://adversa.ai/blog/claude-code-security-bypass-deny-rules-disabled/)
**Type:** fundamenteel
**Toelichting:** Dit is het meest urgente inzicht van de week. Claude Code negeert stilzwijgend door gebruikers geconfigureerde security deny-regels wanneer commando's meer dan 50 subcommando's bevatten. Dit betekent dat je deny-lijst een vals gevoel van veiligheid geeft bij complexe operaties. Tot Anthropic dit fixt: beperk de scope van individuele taken, gebruik OS-niveau sandboxing als extra laag, en vertrouw niet uitsluitend op deny-regels voor kritieke beveiliging.

```yaml
# Mitigatie: gebruik altijd OS-niveau sandboxing naast deny-regels
# In je Claude Code settings:
sandbox:
  enabled: true
  network: restricted
  filesystem: project-only
# Splits complexe commando's in kleinere taken (<50 subcommando's)
```

## Paradigma-check

### 1. Deny-regels zijn geen beveiliging — ze zijn een suggestie

De ontdekking dat deny-regels stilzwijgend worden genegeerd bij >50 subcommando's (adversa.ai) en dat Claude Code zijn eigen sandbox kan omzeilen via path-tricks (ona.com) stelt de gangbare aanname ter discussie dat configuratie-gebaseerde beveiliging voldoende is. **De nieuwe aanname moet zijn:** alleen OS-niveau isolatie (kernel-level sandboxing, containers) is betrouwbaar. Alles daarboven is defense-in-depth, niet primaire beveiliging.

### 2. Meer context ≠ betere resultaten — de 33K-buffer paradox

De 1M context window is GA, maar de autocompact buffer is juist verlaagd. Dit lijkt tegenstrijdig maar onthult een dieper inzicht: het model presteert beter met schone, gefocuste context dan met maximale context. Het paradigma verschuift van "geef het model alles" naar "geef het model precies wat het nodig heeft." Proactief compacten bij 60% in plaats van bij waarschuwingen bevestigt dit.

### 3. Opus 4.6 + medium effort = degradatie bij complex werk

De combinatie van adaptief denken, verlaagd standaard effort-niveau en verborgen thinking-output heeft geleid tot meetbaar slechtere resultaten bij complex engineering-werk. Dit stelt de aanname ter discussie dat nieuwere modelversies automatisch beter zijn voor alle use cases. **De nieuwe praktijk:** forceer expliciet hoger effort-niveau voor complexe taken en monitor of thinking-output zichtbaar blijft.

### 4. Agentic systemen optimaliseren voor actie, niet voor dialoog

Het meest filosofische inzicht komt van dev.to (Pitfalls of Claude Code): agentische systemen zijn ingericht om te *handelen*, niet om te *interageren*. LLM's zijn eigenlijk goed in verbale verkenning van ideeën, maar de agentic harness dwingt ze in een uitvoeringsmodus. Dit suggereert dat een expliciete "dialoogfase" vóór implementatie (plan mode, conversation-first) geen luxe is maar een noodzaak — je moet bewust ruimte creëren voor het type interactie waar LLM's het sterkst in zijn.

### 5. De meeste community skills maken het erger, niet beter

Zes maanden testen door Engr Mejba Ahmed concludeert dat de meeste gepubliceerde skills de output verslechteren. Dit stelt de aanname ter discussie dat een groeiend ecosysteem automatisch waardevol is. **De nieuwe houding:** wantrouw skills totdat je ze individueel hebt getest en gemeten.
