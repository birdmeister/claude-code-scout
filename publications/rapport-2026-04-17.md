

# Claude Code Scout — weekrapport 17 april 2026

## Samenvatting

Deze week was buitengewoon rijk aan Claude Code-ontwikkelingen. Drie thema's domineren:

1. **Claude Managed Agents & Routines** — Anthropic lanceerde twee fundamentele nieuwe mogelijkheden: Managed Agents (gehoste agent-uitvoering in openbare beta sinds 8 april) en Routines (cloud-gebaseerde automatiseringen die op schema, API of GitHub-events draaien, preview sinds 14 april). Dit verandert de manier waarop Claude Code ingezet kan worden fundamenteel.

2. **Context engineering vervangt prompt engineering** — Meerdere onafhankelijke bronnen convergeren op hetzelfde inzicht: de structuur rondom een taak (CLAUDE.md, skills, sessiemanagement, compaction-strategie) bepaalt de output-kwaliteit meer dan de formulering van individuele prompts. Anthropic's eigen blogpost over sessiebeheer en 1M context bevestigt dit.

3. **Opus 4.7 breaking changes** — Het nieuwe model verandert standaardgedrag waardoor bestaande prompt-scaffolding kan breken. Wie Opus gebruikt moet zijn promptbibliotheek reviewen.

Omdat je huidige setup nog niet beschreven is, worden alle inzichten als potentieel nieuw behandeld. Het is sterk aan te raden om je setup-bestand in te vullen zodat toekomstige rapporten beter kunnen filteren.

### Commands & Custom Slash Commands

**Voorstel:** Implementeer het Agent Skills Standard als basis voor custom commands
**Bron:** Volodymyr Nehir, DEV Community — [How to Build Custom Commands for Claude Code Using Agent Skills Standard](https://dev.to/volodymyr_nehir/build-custom-commands-for-claude-code-using-agent-skills-standard-pfd)
**Type:** fundamenteel
**Toelichting:** Skills zijn de door Anthropic aanbevolen aanpak voor commands omdat ze ondersteunende bestanden, scripts en geavanceerde configuraties toestaan. Het verschil met gewone slash-commands: skills activeren automatisch wanneer de conversatie aansluit bij hun ontwerp, terwijl commands wachten op een expliciete aanroep. Dit geeft je een gelaagd systeem: skills voor contextafhankelijke kennis, commands voor expliciete acties.

```yaml
# Structuur voorbeeld
.claude/
  commands/          # Expliciete slash-commands (/project:deploy, /project:review)
    deploy.md
    review.md
  skills/            # Automatisch geactiveerde kennispakketten
    testing/
      SKILL.md       # Alleen processtappen
      references/    # Referentiebestanden apart
```

### Hooks

**Voorstel:** Implementeer event-driven hooks voor linting, testing en notificaties
**Bron:** Felo AI — [Claude Code Hooks: The Complete Guide to Automating Your Workflow](https://felo.ai/blog/claude-code-hooks-guide/)
**Type:** fundamenteel
**Toelichting:** Hooks zijn shell-commands die automatisch reageren op Claude Code-events (pre-tool-use, post-tool-use, notificaties). Hiermee automatiseer je routinetaken zonder handmatige tussenkomst. Denk aan: automatisch linting na elke bestandswijziging, tests draaien na code-generatie, desktop-notificatie wanneer een langlopende taak klaar is.

```yaml
# Voorbeeld hooks configuratie in .claude/settings.json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "command": "npx eslint --fix $CLAUDE_FILE_PATH"
      }
    ],
    "Stop": [
      {
        "command": "osascript -e 'display notification \"Claude is klaar\" with title \"Claude Code\"'"
      }
    ]
  }
}
```

**Aanvullende bron:** Anthropic's officiële hooks-documentatie — [Automate workflows with hooks](https://code.claude.com/docs/en/hooks-guide)

### Skills & Kennispakketten

**Voorstel:** Structureer SKILL.md als pure processtappen en verplaats referenties naar aparte bestanden
**Bron:** MindStudio — [What Are Claude Code Skills and How Do They Work?](https://www.mindstudio.ai/blog/what-are-claude-code-skills)
**Type:** fundamenteel
**Toelichting:** SKILL.md is alleen voor processtappen; alles anders gaat in referentiebestanden. Dit is cruciaal voor context-efficiëntie: Claude laadt alleen de SKILL.md in context, en trekt referentiebestanden pas aan wanneer nodig. Zonder deze scheiding draag je onnodige tokens mee in elke interactie.

```yaml
# Correcte skills-structuur
.claude/skills/
  code-review/
    SKILL.md              # Alleen: "1. Lees de diff. 2. Check X. 3. Rapporteer Y."
    references/
      style-guide.md      # Wordt alleen geladen wanneer SKILL.md ernaar verwijst
      security-checklist.md
      patterns.md
```

---

**Voorstel:** Behandel skills als "expertisekaarten" — herbruikbare domeinkennis die Claude on-demand laadt
**Bron:** Jonathan Fulton, Medium — [Agent Skills: The Cheat Codes for Claude Code](https://medium.com/jonathans-musings/agent-skills-the-cheat-codes-for-claude-code-b8679f0c3c4d)
**Type:** fundamenteel
**Toelichting:** Het verschil tussen een generieke AI-assistent en een die je werk kent, zit in skills. Zonder skills draagt elke agent alle domeinkennis in context; met skills laadt elke agent exact de kennis die nodig is. Dit is de hefboom voor projectspecifieke kwaliteitsverbetering.

## Paradigma-check

### 1. Context engineering > prompt engineering
**Status:** Paradigmaverschuiving — breed bevestigd

Meerdere onafhankelijke bronnen deze week (Anthropic zelf, The AI Corner, Rick Hightower, Martin Fowler) convergeren op hetzelfde inzicht: de kwaliteit van Claude Code-output wordt primair bepaald door de structuur rondom de taak — CLAUDE.md, skills, sessiemanagement, compaction — niet door de formulering van individuele prompts. Dit is niet langer een experimenteel idee maar een mainstream best practice. **Als je nog tijd besteedt aan het perfectioneren van prompts in plaats van aan het optimaliseren van je context-architectuur, investeer je in de verkeerde laag.**

### 2. De ontwikkelaarsrol verschuift naar AI-supervisor en systeemontwerper
**Status:** Trend in versnelling

Meerdere bronnen (exceeds.ai, unite.ai, Anthropic's Agentic Coding Trends Report) beschrijven dezelfde verschuiving: de ontwikkelaar wordt minder codewriter en meer AI-supervisor met expertise in prompt design, agent-coördinatie en AI-output evaluatie. Claude Managed Agents en Routines versterken deze trend door het mogelijk te maken om agents autonoom te laten draaien zonder direct toezicht. **De vraag is niet óf je workflow verandert, maar hoe snel je de transitie maakt.**

### 4. Applicatief sandboxing is onvoldoende voor productie
**Status:** Nuancering van bestaande aanname

Truefoundry's analyse stelt dat OS-level sandboxing in Claude Code padtrucs en escape-pogingen niet volledig voorkomt. Voor productie-omgevingen zijn microVM-isolatie en infrastructuurafdwinging nodig. **Als je Claude Code gebruikt voor code die naar productie gaat, heroverweeg dan of de standaard sandbox voldoende is voor jouw dreigingsmodel.**
