

# Claude Code Scout — weekrapport 20 maart 2026

## Samenvatting

Een uitzonderlijk rijke week voor Claude Code. Drie ontwikkelingen springen eruit:

1. **Agent Teams is live** — een nieuw experimenteel feature voor multi-agent orkestratie waarbij Claude Code-sessies direct met elkaar communiceren, niet alleen via de hoofdagent. Dit is de grootste architectuurverandering van het kwartaal.
2. **1 miljoen tokens contextvenster is GA** — geen pricing premium, 15% minder compaction events, 90% retrieval-nauwkeurigheid over het hele venster. Dit verandert fundamenteel hoe je met lange sessies omgaat.
3. **Lokale kennisgraaf reduceert tokens tot 49x** — `code-review-graph` met Tree-sitter bouwt een lokale dependency-graaf die alleen relevante context laadt. Een concrete, implementeerbare kostenreductie.

Daarnaast: Claude Code Channels (Discord/Telegram), voice mode, /loop voor terugkerende taken, Fast Mode (2.5x sneller), en serieuze waarschuwingen over AI-gegenereerde code die 14.3% beveiligingsproblemen bevat versus 9.1% bij menselijke code.

Omdat je huidige setup nog niet beschreven is, worden alle inzichten als nieuw behandeld.

### Agents & multi-agent workflows

**Voorstel:** Implementeer het Agent Teams-patroon voor parallelle, onafhankelijke taken en gebruik subagenten voor gecoördineerde taken.
**Bron:** Han HELOIR YAN, Ph.D., Medium — [Sub-agent vs. Agent Team in Claude Code](https://medium.com/data-science-collective/sub-agent-vs-agent-team-in-claude-code-pick-the-right-pattern-in-60-seconds-e856e5b4e5cc)
**Type:** fundamenteel
**Toelichting:** Agent Teams laten meerdere Claude Code-sessies direct met elkaar communiceren in plaats van alleen via de hoofdagent. Het cruciale onderscheid: subagenten zijn lichtgewicht en delen context (goed voor gecoördineerd werk), terwijl agent teams eigen contextvensters krijgen (goed voor gefocuste, onafhankelijke taken). Verkeerde keuze kost je 7x meer tokens. Dit is het eerste echte multi-agent patroon in Claude Code zelf.

```yaml
# Beslisregel voor agent-keuze
# Subagent: taak vereist gedeelde context, resultaat moet terug naar hoofdagent
# Agent Team: taak is onafhankelijk, kan parallel, eigen scope
#
# Documentatie: https://code.claude.com/docs/en/agent-teams
```

**Voorstel:** Gebruik de Task tool voor parallelle uitvoering via sub-agenten in eigen contextvensters.
**Bron:** claudefa.st — [Claude Code Task Management: Distribute Work Across Agents](https://claudefa.st/blog/guide/agents/task-distribution)
**Type:** klein
**Toelichting:** De Task tool spawnt sub-agenten die parallel werken, elk met een eigen contextvenster. Dit is een directe manier om doorvoer te verhogen zonder het Agent Teams-experiment te activeren.

### Contextmanagement

**Voorstel:** Maak gebruik van het 1M-token contextvenster en heroverweeg je compaction-strategie.
**Bron:** claudefa.st — [Claude Code 1M Context Window: What It Means for Your Workflow (2026)](https://claudefa.st/blog/guide/mechanics/1m-context-ga)
**Type:** fundamenteel
**Toelichting:** Het 1M-token contextvenster is nu GA zonder prijstoeslag. Dit betekent 15% minder compaction events en de mogelijkheid om uren lang zonder contextverlies te werken. Maar let op: de autocompact buffer is teruggebracht van 45K naar 33K tokens, wat 16,5% van je 200K-window reserveert voor compaction overhead. Bij het grotere 1M-venster is dit proportioneel minder, maar je moet weten wanneer je `/compact` handmatig triggert versus wanneer je het systeem zijn gang laat gaan.

```yaml
# Contextmanagement checklist:
# 1. Controleer of je op het 1M-token venster zit (Opus 4.6)
# 2. Monitor compaction events via hooks (zie hooks-sectie)
# 3. Gebruik /clear voor radicale contextwissel, /compact voor behoud van essentie
# 4. Splits werkblokken van >2 uur in aparte sessies als context drift optreedt
```

**Voorstel:** Houd de 33K autocompact buffer in gedachten bij contextplanning.
**Bron:** claudefa.st — [Claude Code Context Buffer: The 33K-45K Token Problem](https://claudefa.st/blog/guide/mechanics/context-buffer-management)
**Type:** klein
**Toelichting:** De verlaging van 45K naar 33K tokens als autocompact-drempel betekent dat compaction eerder optreedt. Bij complexe taken met veel bestanden kan dit onverwacht context wegspoelen.

**Toelichting:** In plaats van hele bestanden naar Claude te sturen, bouwt deze tool een lokale kennisgraaf met Tree-sitter die alleen relevante functies, klassen en afhankelijkheden laadt. # 4. Meet tokenverbruik voor/na met Claude Code's ingebouwde usage tracking

### Hooks

**Voorstel:** Implementeer PreToolUse hooks voor beveiliging en PostToolUse hooks voor audit logging.
**Bron:** claude-world.com — [Hooks System](https://claude-world.com/tutorials/s15-hooks-system/)
**Type:** fundamenteel
**Toelichting:** Hooks zijn gegarandeerd om uit te voeren, anders dan prompt-gebaseerde regels. Een PreToolUse hook die writes naar `.env` of productie-config blokkeert, is niet optioneel advies maar een hard vangnet. Gegeven het Fortune-artikel over AI-agenten die databases vernietigen (zie Paradigma-check), zijn hooks je eerste verdedigingslijn.

```yaml
# Voorbeeld: Blokkeer writes naar gevoelige bestanden
# In .claude/settings.json:
# {
#   "hooks": {
#     "PreToolUse": [
#       {
#         "matcher": "Write|Edit",
#         "command": "bash -c 'echo \"$CLAUDE_TOOL_INPUT\" | jq -r .file_path | grep -qE \"\\.(env|prod|secret)\" && echo \"BLOCK: Gevoelig bestand\" && exit 1 || exit 0'"
#       }
#     ]
#   }
# }
```

**Type:** klein
**Toelichting:** Deze nieuwe hook-types geven controle over hoe Claude informatie opvraagt bij de gebruiker. Nuttig voor het standaardiseren van interactiepatronen of het loggen van beslismomenten.

**Voorstel:** Bekijk de 17 hook events en vier hook types voor een compleet overzicht van automatiseringsmogelijkheden.

### Skills & kennispakketten

**Voorstel:** Implementeer het SKILL.md-formaat met progressieve openbaarmaking (metadata → samenvatting → volledige instructies).
**Bron:** Towards Data Science — [How to Build a Production-Ready Claude Code Skill](https://towardsdatascience.com/how-to-build-a-production-ready-claude-code-skill/)
**Type:** fundamenteel
**Toelichting:** Production-ready skills laden informatie in drie stadia: metadata (~100 tokens) waarmee Claude bepaalt of de skill relevant is, een samenvatting, en pas dan de volledige instructieset. Dit minimaliseert onnodige tokenbelasting en maakt je skills schaalbaarder. Het verschil met een plat SKILL.md-bestand is significant bij projecten met >10 skills.

```yaml
# SKILL.md structuur voor progressieve openbaarmaking:
# ---
# name: mijn-skill
# description: Korte beschrijving (< 100 tokens)
# triggers:
#   - wanneer gebruiker X vraagt
#   - wanneer bestandstype Y wordt bewerkt
# ---
#
# ## Samenvatting
# Middellange beschrijving van aanpak en output
#
# ## Volledige instructies
# Gedetailleerde stappen, codevoorbeelden, randgevallen
```

**Voorstel:** Gebruik de DBS-framework (Direction, Blueprints, Solutions) voor het ontwerpen van skill-workflows.
**Bron:** Geeky Gadgets — [Claude Skills Tutorial 2026](https://www.geeky-gadgets.com/claude-skills-tutorial-2026/)
**Type:** klein
**Toelichting:** Een gestructureerde aanpak voor het combineren van skill.md, contextuele referenties en scripts tot samenhangende workflows.

**Voorstel:** Merk op dat commands en skills zijn samengevoegd — bestanden in beide locaties creëren dezelfde /slash-command interface.
**Bron:** Bozhidar Batsov, batsov.com — [Essential Claude Code Skills and Commands](https://batsov.com/articles/2026/03/11/essential-claude-code-skills-and-commands/)
**Type:** klein
**Toelichting:** Als je nog aparte commands en skills hebt, kun je ze consolideren. Dit vereenvoudigt je setup.

## Paradigma-check

### ⚠️ AI-gegenereerde code bevat significant meer beveiligingsproblemen

**Bron:** Tech Insider — [AI Coding Tools 2026](https://tech-insider.org/ai-coding-tools-2026-transforming-software-development/)
Stanford/MIT-onderzoek toont 14.3% beveiligingsproblemen in AI-gegenereerde code versus 9.1% in menselijke code. Dit ondermijnt de aanname dat meer AI-code automatisch beter is. **Implicatie:** Elke workflow die Claude Code-output niet actief verifieert op security, is risicovol. De multi-agent code review (zie Testing) wordt hiermee niet optioneel maar essentieel.

### ⚠️ AI coding assistants bereiken een kwaliteitsplateau — en mogelijk een daling

**Bron:** Jamie Twiss, IEEE Spectrum — [Newer AI Coding Assistants Are Failing in Insidious Ways](https://spectrum.ieee.org/ai-coding-degrades)
Nieuwere LLM's genereren code die oppervlakkig correct lijkt maar subtiel faalt. Dit is erger dan de syntaxfouten van eerdere modellen, omdat het moeilijker te detecteren is. **Implicatie:** Test-driven development en geautomatiseerde reviews zijn niet slechts "nice to have" — ze zijn je enige verdediging tegen code die compileert maar verkeerd werkt.

### ⚠️ Een AI-agent vernietigde de volledige database van een ontwikkelaar

**Bron:** Fortune — [An AI agent destroyed this coder's entire database](https://fortune.com/2026/03/18/ai-coding-risks-amazon-agents-enterprise/)
Concreet incident waarbij over-vertrouwen op een AI-agent leidde tot productie-dataverlies. Amazon onderzoekt of AI-assistenten bijdragen aan outages. **Implicatie:** PreToolUse hooks die destructieve operaties blokkeren, zijn niet paranoia maar hygiëne. Combineer met git hooks en branch protection.

### ⚠️ AI-coderingsassistentie reduceert vaardigheidsbeheersing met 17%

**Bron:** InfoQ — [Anthropic Study: AI Coding Assistance Reduces Developer Skill Mastery by 17%](https://www.infoq.com/news/2026/02/ai-coding-skill-formation/)
Junior-ingenieurs die AI voor codegeneratie inzetten scoren onder 40% op begripstests. Conceptuele vragen stellen leidt tot 65% scores. **Implicatie:** Als je Claude Code gebruikt om te leren, stel dan "waarom"-vragen in plaats van code te laten genereren. Overweeg een CLAUDE.md-regel die Claude dwingt beslissingen te motiveren.
